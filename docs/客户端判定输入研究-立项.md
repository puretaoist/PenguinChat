# 客户端判定输入研究 · 立项台账（设备 / 上报 / 行为 / 账号）

> 2026-11-09 立项。目的：**服务端是黑盒，但客户端是传感器**——把官方客户端"采集什么、上报什么、在什么时机报"逐项逆向清楚，就等于拿到服务端判定的"输入清单"，再拿它对照我们自实现协议缺什么、假什么。
>
> 纪律：每条结论必须带证据位置（反编译文件:行 / so 地址 / 参考实现文件:行）；**没挖到就写"未确认"，不许猜**。

## 5.5 上报维度结论（2026-11-09 jadx 反编译实测）
| 上报源 | 进登录链? | 证据 |
|---|---|---|
| Turing(turingfd) | **否** | `com/tencent` 全量搜 `import com.tencent.turingfd / TuringIDService / getTuringDID` = 0 命中 |
| 灯塔 tvkbeacon | 旁路 | 独立埋点 SDK，内含 `com/tencent/tvkbeacon/g/QimeiSDK`；QIMEI 经它产出后进 0x545，SDK 不进登录判定 |
| 登录结果上报 | **是** | `WtloginHelper.RequestReport`→`request.aa`(RunReq 7)、`RequestReportError`→`request.v`(RunReq 8)，带 sig/sig_key/uin/appid，各登录分支都发 |
| DeviceReport 设备指纹 PB | **是** | `oicq/wlogin_sdk/pb/device_report.DeviceReport`（bootloader/version/codename/incremental/fingerprint/boot_id/android_id/baseband/inner_ver），`util.get_android_dev_info`(util.java:957-997) 构造 |
| report_t2/t3 + Reporter | **否（本地）** | `Reporter.write_tofile/read_fromfile` 落盘，本地登录流水，不联网 |

**定论**：登录风控的上报输入 = 登录 TLV + DeviceReport 设备指纹 PB + 登录结果回执(aa/v)。Turing/灯塔为旁路，不进登录判定。
**已核实（2026-11-09）**：DeviceReport = TLV **0x52d**；本项目 `qq8_tlv.dart:1678-1701` 已完整实现（9 字段，全取真机值，顺序对齐 `device_report.java` 的 `__fieldMap__`），**不缺**。上报维度无明显缺口——登录结果回执(aa/v)未发，但属统计/补偿用途，非登录判定必需。

## 5.6 行为维度结论（2026-11-09）
- 客户端**不向登录链上报"操作时序/频率"**；登录频率/时间/地点由**服务端按登录请求自然统计**（IP/时间），客户端无需上报。
- 客户端旁路：① MSF `StatReportManager`(RdmReq: eventName/isSucceed/elapse/size) = 网络连接质量统计（运维）；② 灯塔 `UserAction` + `ActivityLifecycleCallbacks` = 页面/事件埋点（统计）；③ 本地 `report_t2/t3`(Reporter 落盘) = 本地登录流水。**均不进登录风控判定**。
- 结论：**无需补"行为时序上报"**；只需纪律性低频 + 稳定 IP + 非机器人化高频（服务端按请求统计）。

## 6. 定论提醒（避免误用）
- 能"查出"的是**输入特征**；**服务端怎么加权/阈值仍黑盒**，客户端照不出来。
- 档案参数一致 ≠ 身份一致（androidId/qimei 因包名隔离与官方 QQ 不同），见前述讨论。
