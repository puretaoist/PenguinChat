# 日常登录 · 真机验收清单

> 目标：证明「首次验证 → 票据缓存 → 冷启动免验证 → 票据失效重验」这条**日常链路**在真机上成立。
> 这是产品能不能天天用的唯一判据；协议细节（0x544/0x553）不在此清单范围。
> 配套说明见 `docs/PITFALLS.md` C65/C66/C70，代码位置以 `file:line` 为准（改代码请同步改本文件）。

## 0. 前置

| 项 | 值 |
|---|---|
| 包名 | `com.example.qqclient`（`android/app/build.gradle.kts:82`；`.test` 后缀是 TIM 探针包，**不用于本清单**） |
| 构建 | `flutter build apk --debug` → `build/app/outputs/flutter-apk/app-debug.apk` |
| 设备 | 真机、能上网、账号能收短信（短信链才走得通） |
| 数据目录 | `/data/user/0/com.example.qqclient/files`（日志在其 `logs/`） |

```bash
ADB=/c/Users/Administrator/AppData/Local/Android/Sdk/platform-tools/adb.exe
PKG=com.example.qqclient
DAY=$($ADB shell date +%F | tr -d '\r')
LOG=files/logs/qqclient-$DAY.log
```

**起 App（不依赖 Activity 名）**
```bash
$ADB shell am force-stop $PKG
$ADB shell monkey -p $PKG -c android.intent.category.LAUNCHER 1
```

**取日志**（`run-as` 只对 debug 包有效；release 包改用 `logcat`）
```bash
$ADB exec-out run-as $PKG cat $LOG > /tmp/app.log
grep -nE "启动自动登录|设备身份来源|客户端档案|协议线已上线|准入拒绝|冷却|没有可用票据" /tmp/app.log | tail -40
```

## 验收 0 · 首次登录（基线，先做这一条）

1. `adb shell pm clear $PKG`（=全新设备）
2. 起 App → 账号 + 密码 → 应用内滑块 →（若提示）短信码 → 进聊天

**PASS**
- 状态到「已上线」，能收到一条消息
- `files/qq8/qq8-token-<uin>.json` 存在，mtime = 本次
- `files/qq8/device.json` 里 `ksid`、`qimei` 已写入（这两个只有登录成功后才有：ksid 来自 0x108，qimei 来自灯塔）
- 日志有：`客户端档案:`、`设备身份来源: 本机采集 →`

**取证**
```bash
$ADB shell run-as $PKG ls -l files/qq8
$ADB exec-out run-as $PKG cat files/qq8/device.json > /tmp/device-after-first-login.json
```

> 记下 uin、device.json 全文——后面三条都要跟它比对。

## 验收 1 · 冷启动免验证（本清单的核心）

前置：验收 0 已成功（票据在盘上）。

1. `am force-stop`（**不要** `pm clear`）
2. 起 App，开始计时

**PASS（四条全满足）**
1. 全程**没有出现**密码框 / 滑块
2. 60 秒内状态「已上线」，能收发消息
3. 日志出现 `启动自动登录：用保存的票据登录 <uin>`
4. 日志**没有** `断线恢复：没有可用票据`

**FAIL**
- 出现「服务端拒绝登录」/「登录失败」
- 停在「连接中…」超过 120 秒
- 出现密码框（说明票据没被读到 → 去查 `files/qq8/` 是否有 token 文件）

**取证**：`/tmp/app.log` 尾部 80 行 + 一张截图。

## 验收 2 · 票据失效 → 回退重验

**制造一张坏票**（保留字段形状、只毁签名）
```bash
$ADB shell run-as $PKG sh -c 'cd files/qq8 && cp qq8-token-<uin>.json /sdcard/tok.bak && ls'
# 把 tgt 的 hex 前若干位改成 00（字段长度不变，服务端才会回 type=16 而不是解析错）
```
> 不要直接删文件测这一条——删文件测的是「没有票据」，不是「票据过期」。

**期望**：服务端回 `type=16`

**现状判据（按当前代码，这两条必须成立）**
- 日志：`服务端准入拒绝 type=16（…）——不再自动重试`
- UI：`服务端拒绝登录` + `服务端返回 type=16`
- **`files/qq8-login-cooldown.json` 不存在** ← 16 不进风控冷却（`lib/client_api/qq8_providers.dart:643-644` 的 `_isRiskRejection` 只认 45/235/243）
- 再 force-stop 起来、手动点「登录」，**立刻发包**（不被 30 分钟冷却拦住）

**⚠️ 已知缺口**：现在不会自动回到验证页，要用户自己点「登录」。见文末 §缺口 1。

## 验收 3 · 设备身份稳定

1. 连续冷启动 3 次（每次 force-stop 再起）
2. 每次抓：`files/qq8/device.json` + 日志里的 `设备身份来源: 本机采集 → …`

**PASS**
- 三次的 `androidId`、`mac`、`guid` **完全一致**
- device.json 的 mtime 只在首次登录那次变（之后没有新 ksid/qimei 就不该变）

**反例（必判 FAIL）**
- 日志出现 `设备身份来源: 无（采集不到本机信息）→ 退回合成派生`
  ⇒ 这台机器采不到身份，退化成按 uin 合成 → **票与设备对不上 → 237**。这就是不能日常用的机型。

**记录**：`pm clear` 前后的 device.json 差异，作为「重装即换新设备」的实证（官方同款行为，不是 bug）。

## 验收 4 · 多账号切换

1. A 号登一次 → 退出（或直接 force-stop）
2. B 号登一次 → force-stop → 起 App

**PASS**
- `files/qq8/` 下有两个 `qq8-token-<uin>.json`
- 冷启动选**最新修改**的那个（日志 `启动自动登录：用保存的票据登录 X`）

**⚠️ 已知缺口（这条会 FAIL，是代码问题不是测试问题）**
`lib/client_api/qq8_providers.dart:859-863` 建的是 `ChatStore(dataDir: dataDir)`，而会话库固定是 `files/chats.json` + `files/chats/*.jsonl`（`lib/client_api/chat_store.dart:1252-1257`），**没按 uin 分目录**。
判据：B 号上线后仍看到 A 号的会话；或同一个群号的消息串到另一个账号。
修复方向：按 uin 分子目录 `files/qq8-sessions/<uin>/`，chats.json / chats/ / media/ 一起搬。见 §缺口 2。

## §缺口（静态检查发现，改代码需先确认）

1. **type=16 / 155 被当成「服务端拒绝」，没有「重新验证」出口**
   `lib/client_api/qq8_login_service.dart:3476-3489` 用 `isServerRejected()` 把 45/155/16 一起判成 `rejected`，UI 走 `lib/ui/pages/qq8_connect_page.dart:640-665` 的拒绝话术（「等 30 分钟、换账号」）。
   但 **16 是票据自然过期**，是日常最常发生的一种；对着它说「换账号」是错的。
   建议：`resultType == 16 || 155` → 落 `idle`（或 `failed`）+ 文案「登录已过期，请重新验证」，并自动回到验证页；45/235/243 保持现有拒绝话术与冷却。

2. **ChatStore 未按 uin 隔离**（见验收 4）：`lib/client_api/qq8_providers.dart:859-863` 用全局 dataDir。
   建议：`dataDir: Directory('${dataDir.path}/qq8-sessions/$uin')`，并把既有 chats.json/chats/media 做一次性迁移。

> 这两条不改也能跑验收 0–3；验收 4 会直接暴露缺口 2。
