# 通知栏直接回复（方案 A：进程存活时即时发送）

日期：2026-11-01
状态：**已实现 + 离线测试通过 + 真机结构验证；功能验证需要收到消息后在通知栏里实际操作一次**。

## 需求

长按通知 / 展开通知，能直接打字回复，不用点进应用（Telegram、微信都有）。

## 结论与边界（先说清楚）

**能做的**：应用进程还活着（Flutter 引擎在，即连接还在收消息）时，通知栏可以输入文字直接发出去，
发完那条会话的通知自动消失。

**做不到的**：进程已被系统回收后，通知本身也就不存在了；如果用户先把通知留着、
之后进程被杀，再点回复，是没有通道能发出去的——此时**不静默丢弃**，而是把通知换成
一条「回复未发送 … 点按进入会话重发」。

为什么不做"冷启动补发队列"（方案 B）：那样会出现"隔几小时突然替用户发出一条昨天的消息"，
语义上比失败更糟。要真正随时随地回，必须有常驻推送通道（TG 是自建 + FCM），我们暂时没有。

## 实现（原生 → Dart 一条新反向调用）

```text
  ReplyReceiver(广播) ──text/chatId──▶ MainActivity 注册的 dispatcher
      │                                     │ MethodChannel 'penguinchat/notify'
      │                                     ▼
      │                            Dart: MessageNotifier.install(onReply:)
      │                                     ▼
      └─ 成功→撤通知 / 失败→「回复未发送」   MessageNotifyScope._onReplyFromNotification
                                            ▼
                                     ChatStore.send(chatId, [TextSegment(text)])
```

### Kotlin
- 新增 `android/app/src/main/kotlin/com/puretaoist31/penguinchat/ReplyReceiver.kt`
  - `RemoteInput.getResultsFromIntent(intent)` 取 `reply_text` + `chat_id`；
  - `dispatcher`（由 MainActivity 注册）返回 false ⇒ `MessageNotifier.showReplyFailed`；
  - 成功 ⇒ `MessageNotifier.cancelChat`（系统此时还在"发送中"转圈，必须收尾）。
- `MessageNotifier.kt`
  - 单会话通知加 `addAction(replyAction(context, chatId))`；
  - `replyAction`：`PendingIntent.getBroadcast(..., FLAG_UPDATE_CURRENT or FLAG_MUTABLE)`
    ——**Android 12+ 必须 MUTABLE**，写 IMMUTABLE 系统直接丢这个 action；
    `RemoteInput.Builder("reply_text").setLabel("回复")` + `setAllowGeneratedReplies(true)`；
    requestCode 用 `chatId.hashCode() + 1`，与"打开会话"的 `chatId.hashCode()` 错开；
  - 新增 `cancelChat`（只撤该会话 + 重算汇总）、`showReplyFailed`（`chatId.hashCode()+2`，
    文案含被吞掉的文字预览，点击进会话）。
- `MainActivity.kt`：通道就绪后注册 `ReplyReceiver.dispatcher`（`notifyChannel == null` 时返回 false），
  `onDestroy` 置 null（Activity 没了通道也就没了，不能让广播误判"已投递"）。
- `AndroidManifest.xml`：`<receiver android:name=".ReplyReceiver" android:exported="false"/>`
  ——exported=false，只有本应用自己的 PendingIntent 能唤起。

### Dart
- `lib/ui/platform/message_notifier.dart`
  - `install({Future<bool> Function(String chatId, String text)? onReply})`（幂等，可后补回调）；
  - 反向调用 `reply`：参数校验 → `text.trim()`（只有空白视为没回复，绝不发空消息）→
    `await onReply(chatId, trimmed)` → 把 bool 回给原生。
- `lib/ui/lifecycle/message_notify_scope.dart`
  - `_onReplyFromNotification`：`_store == null` 或 chatId 不认识 → false；
    否则 `store.send(chatId, <Segment>[TextSegment(text)])` → true。
  - 复用 [ChatStore.send]（乐观插入 + 异步确认），所以失败态/重试/落盘/群私聊分流都不用重写。
    断网时返回 true（消息已进队列、气泡上会显示失败），比谎报失败更接近事实。

## 测试

- 新增 `test/message_notifier_test.dart`（3 例，全部通过）：
  1. `reply` 把 chatId/text 交给回调，并把 true 回给原生；
  2. 回调返回 false 时回 false（原生据此换"未发送"通知）；
  3. 空白文本 → false；没装回调 → false。
- `dart analyze lib`：No issues found!
- 真机结构验证：`dumpsys notification` 里该通知的 actions 含 `回复`（RemoteInput），
  见下方验证记录。

## 真机验证（HA2CSJR5 / 25091RP04C / Android 16 API 36）

1. 装 release 包（`adb install -r`，保数据），冷启动自动上线；
2. 让手机后台放着，等一条新消息弹通知；
3. `dumpsys notification` 检查 `actions=...` 是否含 reply action；
4. 在通知栏展开 → 输入文字 → 发送 → 日志应出现
   `通知栏回复已提交 chat=... 长度=...`，且该会话通知消失、聊天页出现这条消息。

**待办**：第 4 步需要真实消息（用户自己发一条），我无法在没有新消息时构造 RemoteInput 结果。

## 已知限制

- 汇总通知（"N 个会话有新消息"）不带回复框：没有单一 chatId 可投递。
- MIUI/HyperOS 需要展开通知才看到输入框；折叠状态只有"回复"按钮。
- 只对"收到的新消息"弹的通知有效；自己发出的消息不产生通知。
