## 3. 失效范围模型（本轮核心修正）

旧行为：`sessionExpired` 时给**整份旧票**写 `invalidatedAtMs/invalidatedType`，下次冷启动整票判死，即使里面还有一条从没试过的材料。

新模型（[qq8_token_store.dart](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_token_store.dart>)）：

| 字段/方法 | 位置 | 语义 |
|---|---|---|
| `invalidatedMaterial` | 字段，JSON 键 `invalidated_material` | 只有哪条恢复材料失效；`null` = legacy 整票 |
| `materialKnownInvalid(m)` | [:172](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_token_store.dart#L172>) | 未失效→false；`invalidatedMaterial==null`→true（legacy 整票）；否则 `==m` |
| `evaluateValidity` | [:257](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_token_store.dart#L257>) | 仅 `invalidated && invalidatedMaterial==null` 才返回 `invalidated`；带材料范围时继续按 expire/unknown 判 |
| `markInvalidated({atMs,type,material})` | [:182](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_token_store.dart#L182>) | 显式重建实例（`copyWith` 的 null=保持原值没法清零材料范围） |

写入点唯一：`_handleResponse` 的 `sessionExpired` 分支 [qq8_login_service.dart:3741-3755](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_login_service.dart#L3741-L3755>)，材料名取自 `_attemptMaterial`（[:387](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_login_service.dart#L387>)，在 `loginWithToken` 选到材料时赋值 [:676](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_login_service.dart#L676>)，口令/短信链清空 [:765](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_login_service.dart#L765>)，成功清空 [:3574](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_login_service.dart#L3574>)）。

兼容性：旧文件没有 `invalidated_material` → `null` → 仍是 legacy 整票语义（**不无证据洗白**）；旧票若 `invalidated` 且无范围，冷启动照旧跳过并要求重验。

## 4. 恢复材料与默认策略（决策表）

`planNext`（[recovery_planner.dart:200](<C:/Users/Administrator/penguis/qqclient/lib/client_api/recovery_planner.dart#L200>)）是唯一决策函数，输入 = 可用性 + 已试集合 + 网络/验证标志 + `allowUnverifiedMaterials`。

| 结束码 | 触发条件 | 本轮动作 |
|---|---|---|
| `network` | `networkError` | 停止，不据此作废材料，不轮换凭证 |
| `challenge` | `challengeActive` | 停止，交人工验证 |
| `unverified` | 手上只有**未经真机验证**的材料（默认模式） | 停止为需要重验，文案「登录凭证不足以自动恢复（只剩未验证的恢复材料），请重新登录一次」 |
| `exhausted` | 无任何可用材料 | 停止为需要重验 |
| `Attempt(material)` | 命中 `qq8VerifiedRecoveryMaterials`（当前仅 `d2Key`，[:188](<C:/Users/Administrator/penguis/qqclient/lib/client_api/recovery_planner.dart#L188>)） | 发包一次 |

## 7. 未验证项与风险

1. **A1 生产端**：`fromSigBundle` 存 `a1=b.t106` 但**不填 noPicSig**（[qq8_token_store.dart:274-299](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_token_store.dart#L274-L299>)），而 A1 分支把入参当「尾部追加 16B tgtgt 的 en_A1」并裁尾当 0x106。格式/来源矛盾未证 ⇒ 首次登录能否自然产出可用 A1 对未知。因此默认关闭是正确的保守结论。
2. **TTL 未知**：`evaluateValidity` 无 `expireAtMs` 时返回 `unknown` 并按「照常尝试」处理，不猜 TTL。
3. **无前台恢复入口**：App resumed 不重评估票据；长时间离线/服务端失效通知与冷启动的规则未共享（本轮未新增，属设计缺口）。
4. **预算不统一**：冷启动 `runSingleFlight`、断线 `_reconnecting` 各自为政，`maxAttempts=4` 只是上限；本轮未改（改动会触及 4000 行服务的状态机，风险大于收益，需专门设计与集成测试）。
5. **`rejected` 不跨进程**：冷启动仍会试一次票据链（有意保留，见 [qq8_providers.dart:610-618](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_providers.dart#L610-L618>) 注释）。
6. **冷却文件全局、按 uin 生效**：A 号冷却不拦 B 号，但文件本身是单文件；并发写未加锁。
