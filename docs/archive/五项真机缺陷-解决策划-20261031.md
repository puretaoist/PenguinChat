## 3. 缺陷2：-10008风暴与恢复迟缓

### 3.1 已证机制与未证边界

- [会话重发](<C:/Users/Administrator/penguis/qqclient/lib/kernel/wlogin8/qq8_session.dart#L246-L293>)：同请求立即重发一次，没有跨请求预算；最终异常未充分保留原命令/重发状态，超时也未覆盖完整发送生命周期。
- [TCP断开与隐式重连](<C:/Users/Administrator/penguis/qqclient/lib/kernel/wlogin8/qq8_tran.dart#L405-L457>)：断开主要处理transport自己的pending；业务write可以在socket为空时新建TCP，session自己的pending与连接代际缺少联动。
- [心跳断线入口](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_login_service.dart#L3792-L3802>)：业务失败未统一驱动恢复，现场等心跳判坏才重连。“新TCP继续旧业务身份”是高可信候选，不宣称已证服务端内部原因。
- [拉取与恢复](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_login_service.dart#L4023-L4141>)：外层timeout不取消底层Future，finally还可能启动群轮询；仅一个布尔single-flight不能保证整条链停止。

### 3.2 实施方案

1. L2增加明确的传输断开/连接代变化事件，由会话消费；事件应幂等。活跃业务session不得悄悄换TCP并复用旧身份。登录前独立send工具若需自动连接，以显式模式保留兼容。
2. 断开时立即终结session所有pending、停止心跳/轮询派生任务、使当前epoch失效。连接建立也single-flight；旧连接的onDone不得清掉新socket。
3. L3只有一个恢复入口，网络通知/业务异常/心跳都交给它；网络恢复通知只提示“一次受控探测”，不是已联网证明，也不绕过安全闸门。
4. 保留有官方依据的单请求最多一次-10008重发；补原请求cmd、seq、resent及总deadline。总deadline覆盖排队、建连、第一次发送和重发，不因重发重置。
5. 会话级增加suspect状态：跨请求短窗内重复耗尽重发预算时，暂停非必要轮询，只保留一个探测/恢复任务。窗口、阈值、退避是本地可注入策略，先由虚拟时钟测试校准，不冒充协议常量。单个-10008不能判凭据失效。
6. 所有异步结果写入前验证epoch/账号；能取消则取消，不能真正取消Future时也必须阻止旧任务继续发包/提交游标/写新账号。finally不能绕过取消检查。
7. 保持最多3次票据恢复及现有拒绝/过期停止规则；不自动改用密码撞登录，不因每个业务错误各发一次登录。用户消息不进入通用恢复重放队列；发送结果未知须诚实呈现，不自动重复非幂等操作。
8. 日志按原因分类，纠正把SSO错误统一称“收包解析失败”；重复失败聚合计数，但首次/状态转换/最终失败必须保留。

### 3.3 离线验收

- 断开后全部session pending立即完成为明确错误，无悬挂到原超时；close可重复调用。
- 新连接代出现后，旧timer、旧拉取及旧onDone都不能发包或覆盖新状态；并发connect只产生一次建连。
- N个并发请求连续-10008，单请求至多重发一次、会话至多一个恢复任务；暂停后写入数不随轮询周期继续增长。
- 假时钟触发业务错误即可进入恢复，不依赖270秒周期心跳；网络事件重复到达不放大恢复次数。
- 断网中的用户发送不被恢复逻辑偷偷重放；auth-dead/rejected/sessionExpired仍停止，预算耗尽后等待用户操作。

## 4. 缺陷1：注册/check超时与推送能力未确认

### 4.1 先解决状态与证据，不先猜协议

- [后台注册](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_login_service.dart#L3920-L3937>) 已经后台执行，不能把方案写成“简单改后台”；catch所有异常为无应答会掩盖身份失效/网络/解码问题。明确拒绝若早于online到达，还可能被阶段判断忽略。
- [QueryHB处理](<C:/Users/Administrator/penguis/qqclient/lib/client_api/qq8_login_service.dart#L2973-L2984>) 缺注册single-flight并忽略false；官方存在条件性重注册，不支持“不理QueryHB一定无业务push”的断言。
- [注册结果解析](<C:/Users/Administrator/penguis/qqclient/lib/kernel/wlogin8/qq8_register.dart#L170-L175>) 优先tag2，但fallback tag9不等于官方确认成功；缺字段不能贸然判成功或拒绝。官方单版本证据支持30秒等待，现阶段不改为fire-and-forget或盲延超时。
- [固定回放局限](<C:/Users/Administrator/penguis/qqclient/lib/kernel/wlogin8/qq8_online_check.dart#L25-L97>) 摘要语义未知、不同长度账号可能仍发捕获账号体、缺档案验证；不能作为跨账号产品能力。

### 4.2 实施方案

1. 每epoch独立记录注册确认状态：pending、confirmed、rejected、unconfirmed（静默超时/缺关键字段等，附reason）、transportFailure；与“已鉴权、可拉取消息”分开。UI不得把unknown写成注册成功，也不因单纯超时假称密码登录失败。
2. 启动/QueryHB共用注册协调器；同epoch最多一个in-flight，另有有界冷却。合并的是任务，不是删除QueryHB语义；不同epoch结果必须隔离。
3. 拒绝无论在connecting还是online到达都按明确结果处理并终结维护任务；SSO auth-dead沿既有停止策略，传输失败交W1。不能只改stage而留下心跳与轮询。
4. 可选setOnlineStatus不再无条件挡上线UI：采用受控后台维护或显式“鉴权完成、维护待确认”状态；需要核实其业务依赖，不能为追求快上线冒充全部在线能力已确认。
5. 摘要未知的check回放默认不作生产前置条件，转显式诊断能力；只在捕获来源账号与完整档案匹配、材料来源有记录时允许。其他账号/档案返回unsupported/skip，绝不发旧账号体；不补猜签名/摘要。
6. 将bool解析升级为有证据的结果类型。tag2缺失为unknown；历史兼容fallback若保留必须标legacy，不能升格confirmed。字段调整前补四版本/oicq对照记录。
7. 加脱敏观测：cmd/seq/epoch、发送/接收计数、retcode、耗时、匹配/迟到/未识别响应、业务push分类、拉取触发源。只记结构及计数，不写payload、票据、密码或完整媒体URL。

### 4.3 推送根因调查门禁

先利用已有离线捕获核对发出命令、响应seq/外层类型/解包失败和回执路径；再核证注册字段与生命周期。若缺相同epoch且确有对端发消息的观察窗口，不得以“零push”证明未注册。
即使修好状态与超时处理，也只能交付“维护链路健壮性改善”；必须观察真实业务push才可宣称推送已修复。若仍无push，保留8秒/60秒轮询兜底并明确能力限制，不以缩短到高频轮询冒充推送。

### 4.4 离线验收

- 确认成功、明确拒绝、静默无回包、畸形/缺字段、身份失效、传输失败分别覆盖；拒绝早于online不被覆盖。
- 100个并发QueryHB只有一个in-flight；冷却后允许一次新任务，切epoch不采纳旧响应。
- 账号位数/值或档案不匹配时check零发包；缺字段/legacy样本不产生confirmed。
- 真正静默transport不立即throw，用虚拟时钟验证超时；不能拿“脚本耗尽立即异常”冒充30秒无回包测试。

2. 优先核证协议结构标志；缺发送者且缺有效时间、头元数据不足的条目可先隔离为无效历史，但不得宣称真实撤回。合法同文、真实撤回及合法sender0系统消息须保留；不能只按sender==0或time==0过滤。
3. 实时水位只认成功响应中实际收到、群归属/请求区间/结构均合理的seq，包括有证据的占位。绝不能用returnEndSeq或请求end推进新消息水位；无可验证seq的坏条目不伪造进度。
4. 向后历史分页在完整请求窗口成功消费后按原始窗口推进，不依赖可见条数。允许visible=[]而next非空；自动跳过空展示页有界。非0结果应分类错误，不当作“历史已到底”；实时真空页仍不推进水位。
5. 旧缓存读取时采用非破坏归一化/隔离视图，原JSONL不清空、不批量删除、不自动重写。只有能识别QQ8群来源及身份/时间缺失组合的旧记录才标legacy-invalid，排除真实撤回/合法系统消息；不足以判定的保留。
6. 时间有效性独立表达，例如兼容可选timeKnown/provenance/classification。未知时间不改成当前时间或邻居时间，不改变消息ID；有真实内容则保留并省略HH:mm/日期胶囊或标“时间未知”。排序用服务端seq/页序保持稳定，不参与正常日期摘要。
7. 隔离条目不进入普通气泡、未读、会话摘要或lastTime；重建显示投影须避免重复递减持久化未读。不能仅修新消息：相同ID旧坏记录不会自然被新记录替换，读取兼容必须覆盖。

### 6.3 离线验收

- 13条合成全占位页、正常混页、合法文本“[已删除]”、真实撤回/揭示/重启、合法sender0系统消息分别覆盖；合成用例不是现场13条原始包复现。
- 全隔离页仍可向前翻到有效历史；占位有合法seq则推进原始水位，但不发普通消息/不涨未读；returnEndSeq远大于真实seq也不越水位。
- result非0不置历史结束，实时空页不前进；缺失/0/负数/超界时间区别处理，未证范围不擅造协议常量。
- 旧缓存无新字段可读，原文件内容未改；重复ID、无法识别来源的旧记录不静默丢失；未知时间无1970日期或08:00气泡且排序稳定。
