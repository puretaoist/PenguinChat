## 1. 决策摘要

1. **第一项先修可独立证明的封包/回执差异，再验证业务推送。** 不再通过加请求、缩短超时、提高轮询频率猜原因。
2. **第二项在错误发布源头拆分连接控制与认证失败。** 不以全局降日志、过滤全部传输异常来“修复”。
3. 注册响应、长连接存活、业务消息实际推送是三个独立观测维度；任何一个都不能替代另两个。
4. 当前最优先的协议候选是：注册的 WUP body 被额外封成 OICQ；ConfigPushResp 的 type 字段号错误及 type3 漏原 data。源码能证明差异，尚不能证明其为唯一线上根因。
5. 当前最明确的错误传播根因是：自动恢复内部先发布 failed，适配器再包装 StateError，ChatStore 再次记 W，之后恢复循环才纠正成 disconnected。
6. 保持已验证产品边界：自动续连只用已验证 D2 材料，无密码回退；认证过期/准入拒绝不盲重试；前台约 8s、后台约 60s 轮询先保留。

### 3.2 最小修复顺序

#### A. 先建立字节层回归门禁（不发网络请求）

- 四 APK + oicq 按“SSO外壳/命令body/OICQ是否存在/JCE字段/回执行为/认证错误”逐项记录，缺 native 证据单列。
- 为真实 send 路径加 fake transport 捕获；解开外层、按已知测试密钥解 SSO、独立定位 body，再断言等于原 WUP。**不能只测 buildBody 或比较当前实现自己产生的 golden。**
- 注册 type=1 应当 SSO(d2key, rawWUP)，不是 SSO(d2key,OICQ(rawWUP))；保持 0x0A 外壳，不擅自改成全部 UNI。
- 校时 type=0 的 body 是4零字节；Heartbeat.Alive 的空 body 要查旧 JS 参考再锁定；密码/票据 wtlogin 的 OICQ 保持原样。
- **flag/type=2 是 SSO 加密选择，不等于任意命令都需要 OICQ。** 两条在线诊断检查虽用 flag2，仍需按各命令已核的 body 格式处理。

#### B. 封包与 ACK 精确纠偏

- 设计显式 body 格式或拆 API：原始 SSO body 与 wtlogin OICQ body 分开，调用者明确选择；避免“type==2 就自动 OICQ”的另一种过度泛化。
- 先限制修复面于已核命令；逐一审计 sendLoginLayer 的注册、校时、Alive、在线检查调用。真正登录构包路径不能被顺手改变。
- 配置回执提取为 L2 纯编解码：合法外层 type/seq 校验后即可确定 ACK 内容；type1/2/未知类型无额外 data，type3 回带原始 data。
- 保留 servant=QQService.ConfigPushSvc.MainServant、method/key=PushResp，SSO seq 取收到帧的 r.seq，body tag2 取 PushReq 的业务 seq，两种 seq 不混用；允许负 SSO seq。
- 扩展配置应用与回执分开 try，合法外层、type2 内层解码坏仍可回执；外层无法安全取 type/seq 时不猜值、不盲 ACK。
- 回执只写不等、不建 pending；写成功只能记“已发”，不能记“服务器已确认”。
- 不顺手新增 PushDomain ACK：本轮仅证命令存在，处理格式未核；保留限量 metadata 诊断与后续离线取证任务。

### 4.2 实施设计

**A. 在信息被字符串化之前保留类型。**

- L2 增加 failure kind/phase，区分 dns、unreachable、noRoute、connectTimeout、refused、permission、readClosed、writeFailed、responseTimeout、framing、decode、unknown。
- 当前 Qq8TransportException 已有 cause，但连接多端点聚合先丢成 List<String>；要在该边界保存每个 EndpointFailure(kind,cause,stack,phase)，仅上层加 enum 不算保真。
- L3 保存 FailureInfo：originOperation、owner、account scope、operation/connection epoch、failureId、cause/stack、retryDisposition、服务端码；显示文案与编排数据分离。L2不反向引Session或Flutter。
- DNS并不等于已证飞行模式；只在相关端点错误均属于可等待网络类时进入等待分支。混合 permission/refused/unknown 不应因总文案“连接失败”无限等待。responseTimeout仍有界，不暗示服务端已收到。

**B. attempt返回结果，由owner决定发布。**

- 内部尝试返回结构化 LoginAttemptResult（online/challenge/authExpired/accessRejected/retryableTransport/otherFailure），保留原cause/stack。
- 用户首次密码、手动票据、验证码/短信、手动重连、后台恢复分别有明确调用context；不能用 token!=null 或全局 _reconnecting 代表所有错误都可静默。
- 自动恢复的可等待网络失败，不先调用通用 _fail；直接发布recovery进度/等待原因。failed仅供真正终态或本次用户动作失败。
- 优先级：认证失效/准入拒绝 > 传输重试。登录续期收到SSO authDead也必须终止，不能只识别wtlogin type16/155后漏掉SSO层码。
- 3次请求未确认预算、15s离线等待、30min等待总期限先维持；stopReason单独区分 exhausted / offlineDeadline / noMaterial / unverifiedMaterial / canceled / authExpired / rejected，不再在实际0次计数时打印“3次均失败”。

**C. 一次逻辑失败只有一个诊断owner。**

- 自动恢复由recovery coordinator记录：首次断线W；重复等待D/I并附计数；恢复成功I；截止/可行动终态W。不是全局降低日志级别。
- adapter只转换，不重复日志；ChatStore对“恢复已接管的瞬态控制事件”只更新连接，不再W。认证终态、未知协议错、真实用户发送/撤回/历史操作失败必须保留。
- 推荐用SessionStateChanged附recovery phase/reason或专门RecoveryProgress承载；SessionFailure保留终态/用户动作错误。若保留可恢复failure，也必须含typed disposition，消费者不得猜字符串。
- 同态更新按(state,reason,phase,epoch)判定；一次性failure按稳定failureId/revision去重。相同文本的两次独立用户错误不得被全局去重。
- online清除旧error；连接等待文案用状态提示样式，认证失败/用户可行动错误保留错误样式。QQ8直接provider与Session契约两条消费路径均需测。

**D. 取消与代际覆盖整个尝试。**

- 保留现有_sessionEpoch守卫，另加recoveryRun/loginOperation代际，覆盖尚无Qq8Session的建连阶段。
- delay、token load、connect、send、catch发布前及材料写入前都核验account/operation/current session；切号、close、新手动登录取消旧run并解除等待，不再发旧请求。
- 错误归属使用发起时捕获的uin/context，不从全局snapshot事后取uin；旧网络失败不能覆盖新认证终态、旧auth结果也不能清新号票据。

## 7. 获单独授权后的最小真机验证

本策划不构成新一轮真机/登录授权。仍用专用测试号，保留本机数据，不用主号、不清数据、不导官方凭据、不hook、不改坏票据制造失效。

1. 先只读确认当前设备、账号范围与构建版本，覆盖安装；正常冷启仅一次，复用已存票据。
2. 收集脱敏收发metadata：account scope/epoch、direction、cmd、seq、retcode、payload长度、pending匹配结果、handler/ACK写入结果、register耗时/分类。默认不记录票据、密钥、完整消息体或设备身份。
3. 完成S1后先确认实际出包解出的body形态；取注册响应或记录未确认。收到ConfigPush只记ACK发送事实，不把它当服务器接受证明。
4. 经协调方授权分别发唯一标识私聊/群消息，在短时诊断窗口区分poll与push：可暂停定时poll，但保留PushNotify触发拉取与明确保护期限，结束自动恢复原poll。消息若只能从手动/定时拉取得到，不计实时push通过。
5. QueryHB若观察到至少两次，检验reason=serverPush、burst合并及结果提交；未到达写“未覆盖”，不主动伪造服务器QueryHB、不为等它反复登录。
6. 一次20–60s断网/恢复验证错误owner与UI；检查持续离线等待、恢复后清错、群/私聊去重；不重复刷账号认证。
7. 遇准入拒绝、过期或新增验证立即停止自动尝试；是否人工重验另获授权。自然过期与多号隔离仍属另外两项验收，不能用模拟当真机通过。

第一项成功至少需要“正确出包 + 合法注册响应可观察 + 经区分来源的业务推送到达”分别给证据；若只有前两项，交付口径是“注册协议纠偏完成，业务推送仍待验证”，不是全部解决。
第二项成功要求“可恢复网络失败不发布伪登录失败 + 日志保留单owner诊断 + 终态/用户动作错误不被隐藏 + 恢复后清错”，不能只看W数量归零。
