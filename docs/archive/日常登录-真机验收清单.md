# 日常登录 · 真机验收清单（2026-10-31 修订版）

> 目标：证明「首次验证 → 票据缓存 → 冷启动免验证 → 凭证失效后重验」这条**日常链路**在真机上成立。
> 协议细节（0x544/0x553、风控归因）不在本清单范围。
> 本版替代旧版：旧版里的 `pm clear`、把票据导出到 `/sdcard`、手工改坏 `tgt`、以及「改坏必回 16 / 换设备必回 237」等说法**已删除**——那些步骤会毁掉用户唯一一份有效凭据，且结论未经证明。
> 配套：恢复链路实现与离线结论见 [docs/日常登录-恢复链路审计与离线收尾报告.md](<C:/Users/Administrator/penguis/qqclient/docs/日常登录-恢复链路审计与离线收尾报告.md>)。

## 0. 铁律（先读，违反即中止）

1. **不 `pm clear`、不清应用数据、不卸载重装**（除非用户明确要求「测重装即换新设备」并接受丢票）。
2. **不导出票据文件**（`files/qq8/qq8-token-<uin>.json`、`.enc`、`qq8-token.key`）到 `/sdcard`、聊天、报告或任何共享位置。需要看结构只看 `ls -l` 与大小。
3. **不手工改坏 `tgt`/`d2` 去「制造过期」**，也不改系统时间。真实过期只**被动观察**。
4. **不用主号**；测试账号由用户指定，风险由用户确认。
5. 一次失败就停：不换档案、不换设备标识、不改参数反复撞同一账号。
6. 设备标识（androidId/mac/guid/qimei/ksid）只在设备上比对**一致性**，不写进报告；截图先遮账号/手机号/验证码。
7. 验证码/滑块/短信由**用户本人**完成，自动化只负责把界面送到那一步。

## 2. 阶段 0 · 只读检查（不清数据、不先启动旧包）

目的：先弄清「现在是什么状态」，避免一启动就自动登录把现场搅乱。

```bash
$ADB shell pm list packages | grep qqclient
$ADB shell dumpsys package $PKG | grep -E 'versionName|firstInstallTime|lastUpdateTime'
# 只列目录与大小，不读内容：
$ADB shell run-as $PKG ls -l files/qq8 2>&1
$ADB shell run-as $PKG ls -l files/logs 2>&1 | tail -5
```

判定：
- 有 `qq8-token-<uin>.json`（或 `.enc`）→ **已有会话**，先做验收 A，不要做首次登录。
- 无票据文件 → 需要首次登录（验收 B），但先确认用户授权与测试号。
- 若设备处于飞行模式/无网，先保持；联网后的自动登录行为属于验收 A 的观察项。

## 3. 验收 A · 已有会话的冷启动恢复（核心）

前置：阶段 0 看到票据文件；网络可用。

1. `am force-stop`（**不要** pm clear）
2. 起 App（不依赖 Activity 名）：

```bash
$ADB shell am force-stop $PKG
$ADB shell monkey -p $PKG -c android.intent.category.LAUNCHER 1
```

3. 计时并抓日志：

```bash
$ADB exec-out run-as $PKG cat $LOG > /tmp/app-A.log
grep -nE '启动自动登录|planner|设备身份来源|客户端档案|协议线已上线|登录凭证|冷却|票据已标记失效' /tmp/app-A.log | tail -40
```

**PASS（全部满足）**
1. 全程**没有**密码框/滑块。
2. 60 秒内「已上线」，能收发消息。
3. 日志有 `启动自动登录：用保存的票据登录 <uin>`，且 `planner` 预演选的是 `d2Key`（或直接 Attempt）。
4. 日志**没有** `登录凭证不足` / `没有可用的票据` / `票据已标记失效`。

**FAIL 分支怎么读**
| 现象 | 含义 | 下一步 |
|---|---|---|
| 出现密码框 | 票据没读到或已被判失效 | 看阶段 0 的文件是否还在；看日志 `跳过 <uin>：票据不可用` |
| `登录凭证不足以自动恢复（只剩未验证的恢复材料）` | 只剩 A1/A2KEY，产品按策略不自动试 | 这是**预期行为**，需用户手动重登；记录该现象 |
| `登录已过期，请重新登录一次` | `sessionExpired`（16/155/authDead） | 走验收 F 的记录流程，不自动重试 |
| `服务端准入拒绝 type=45` | 账号级准入拒绝 | 停止，不换材料撞；记录一次即止 |
| 停「连接中…」>120s | 网络/链路 | 查日志尾部，不要连点 |

4. 记录：`/tmp/app-A.log` 尾部 80 行 + 截图（遮账号）。**不要**把 device.json 拷到主机长期保存。

## 4. 验收 B · 首次登录（仅在确无会话且获授权时）

1. **不** `pm clear`。若确需从零（例如用户换了新设备），由用户决定并知情。
2. 起 App → 输入测试号 + 密码 → 应用内滑块 →（若提示）短信码 → 上线。
3. 判定：

**PASS**
- 状态「已上线」，能收到一条消息。
- `files/qq8/` 出现 `qq8-token-<uin>.json`（或 `.enc`），大小 > 0。
- 日志有 `客户端档案:`、`设备身份来源: 本机采集 →`（若显示「无（采集不到）→ 合成派生」，见下方 FAIL）。
- `device.json` 里出现 `ksid`/`qimei` 属**加分**，不是硬性判据：服务端不一定下发。

**FAIL**
- `设备身份来源: 无（采集不到本机信息）→ 退回合成派生` ⇒ 该机型日常不可用（票与设备绑不上），记录机型后停。
- 密码正确却 `type=45` ⇒ 账号级准入拒绝，停止（见 §8）。

## 5. 验收 C · 断网与前后台恢复

1. 上线后开飞行模式 1–2 分钟，再关。观察是否自动回到在线（`断线恢复：第 n/3 次（票据续期）` → `协议线已上线`）。
2. 按 Home 再回 App，确认会话仍在、不需要重新验证。

**PASS**：恢复后能发一条消息且**不重复**发送断网前的旧消息；不超过 3 次重连就停（超了应显示「自动重连失败…请手动重新登录」）。

> 说明：当前**没有**独立的「前台恢复重评估」入口（resumed 不换票）；本条只验不崩、不重复发包。

## 6. 验收 D · 消息与表情

1. 收一条私聊、一条群消息；在群里发一条**单表情**消息。
2. **PASS**：群消息能进对应会话；单条表情只出现**一个**气泡（不重复）；重启 App 后历史仍在、不重复。

## 7. 验收 E · 多账号隔离（需用户提供第二个测试号）

1. A 号登录产生会话/草稿/未读 → 切 B 号登录 → 回 A 号。
2. **PASS**：
- `files/qq8/` 下两份票据文件；`files/accounts/<uin>/` 各自独立。
- B 号看不到 A 号的会话、草稿、未读、媒体；反之亦然。
- 冷启动选**最近修改**的那份票据（日志 `用保存的票据登录 X`）。

> 若失败，先看 `ChatStore` 是否按 `accounts/<uin>` 落盘，再报缺陷；不要用旧版清单的「chat 文件未隔离」结论（已在前序提交修复）。

## 8. 验收 F · 真实凭证过期（只观察，不制造）

日常使用中自然出现 `sessionExpired` 时记录：
- 日志：`票据已标记失效（type=... 材料=...）`，`材料=` 应指向本次真正走过的分支（`d2Key`/`a2Key`/`a1NoPicSig`/`整票`）。
- UI：`登录已过期` + 「重新登录」按钮；点它 → `resetForRelogin` → 回 idle 等用户输入，**不自动发密码**。
- 重登成功后，旧失效记录被新票覆盖（成功路径新建 token）。

**禁止**为了触发本条去改坏票据或改系统时间。

## 9. 判读速查

| 现象 | 日志关键词 |
|---|---|
| 冷启动走票据 | `启动自动登录：用保存的票据登录` |
| 决策预演 | `planner` / `Attempt` / `Stop` |
| 没有可用材料 | `登录凭证不足，请重新登录一次` |
| 只有未验证材料 | `登录凭证不足以自动恢复（只剩未验证的恢复材料）` |
| 失效范围写入 | `票据已标记失效（type=... 材料=...）` |
| 设备身份 | `设备身份来源:` |
| 准入拒绝 | `服务端准入拒绝 type=`（45/235/243 → rejected） |
| 断线重连 | `断线恢复：第 n/3 次` |
| 冷却 | `登录冷却中` / `冷却到` |

## 11. 停止条件

- 出现 `rejected`（45/235/243）：一次即停，等用户决定。
- 出现异常验证/账号限制/用户取消：停，汇报。
- 自动恢复超过 3 次或超过 3 分钟：停，交人工。
- 任何需要清数据、导票、改包才能继续的步骤：停，先问用户。
