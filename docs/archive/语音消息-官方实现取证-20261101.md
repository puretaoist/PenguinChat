## 0. 一句话结论

| | QQ 8.2.11 | Telegram Android |
|---|---|---|
| 采集 | AudioRecord 16000Hz / 单声道 / PCM16（不是 MediaRecorder） | AudioRecord 48000Hz / 单声道 / PCM16，20ms(960 样本) 一帧 |
| 编码 | **SILK v3**（libcodecsilk.so，16kbps），另有 legacy AMR-NB 分支 | **OPUS**（jni 内 libopus，VOIP 模式，VBR 不封顶，帧长 20ms），封 Ogg Opus |
| 文件 | `0x02 + "#!SILK_V3"`（10 字节头）+ 每帧 `2B 小端长度 + SILK 帧` | `.ogg`（OpusHead + OpusTags + Ogg pages，带 preskip/granulepos） |
| 时长 | dataLen / bytesPerSec，四舍五入到整秒 | 样本数 / 48000（秒，double） |
| 上传 | SSO `cmd0x346 APPLY_UPLOAD-500` 拿 upload_ip/ukey/uuid → **HTTP 传原始文件**（群走 BDH） | MTProto `upload.saveFilePart`，128KB 片、≤16 并发、<10MB 直传小文件 |
| 发送信令 | `RichText.ptt`（消息 msgtype = **-2002**），带 uuid/md5/size/time/format/down_para | `messages.sendMedia` + `TL_document(mime audio/ogg)` + `DocumentAttributeAudio(voice=true, duration, waveform)` |
| 下载 | `cmd0x346 APPLY_DOWNLOAD-1200` 拿 URL → HTTP + `Range` → 落盘 `.slk`/`.amr`；下完回执 `cmd=1000` | FileLoader 按 `dc_id + "_" + id + .ogg` 落缓存；`tg://` 自定义 DataSource **边下边播** |

## 1. 官方 QQ 8.2.11（PTT）

- **录制**：`com.tencent.mobileqq.utils.QQRecorder`。`QQRecorder$RecorderParam(16000,16000,1)` = 采样率 16000 / 码率 16000 / 音频类型 1(SILK)；`b()` 里 `new AudioRecord(audioSource, 16000, 2, 2, bufferSize)`（2=MONO，2=PCM16），缓冲区 `getMinBufferSize(...)` 兜底。噪声抑制节点用 `libwechatns.so`。
- **编码**：`com.tencent.mobileqq.utils.SilkCodecWrapper`，native `SilkEncoderNew(sampleRate, bitRate) / SilkDecoderNew / encode / decode / deleteCodec`，加载 `libcodecsilk.so`（`SoLoadUtil.java:14-15`）。so 内符号 `SKP_Silk_SDK_Encode/SKP_Silk_SDK_Decode`（Skype 参考实现），参数可 `SetSampleRate/SetBitRate/SetPacketSize/SetComplexity/EnableInBandFEC`。
- **文件结构**（`bbfl` 类，逐字节）：头 10 字节 = `0x02` + `"#!SILK_V3"`（0x02 是采样率下标，16000→2）；之后每帧先写 2 字节**小端**长度再跟 SILK 帧。AMR 分支头是 `"#!AMR\n"`。
- **信令**：`MessageForPtt.getRichText()` 填 `im_msg_body.RichText.ptt`（字段定义见 `jadx-main/sources/tencent/im/msg/im_msg_body.java:601-626`）。C2C：`bytes_file_name = md5 + ".amr"`、`uint32_file_type=4`、`bytes_file_uuid=urlAtServer`、`bytes_file_md5`、`uint32_file_size`、`bytes_down_para=directUrl`；群：多 `uint32_file_id`、`uint32_format=voiceType`、`uint32_time=秒`、`bytes_group_file_key`。
- **命令字澄清**：`0x352` 是图片上传（TryUpImgReq），**与语音无关**；语音用 `0x346`（APPLY_UPLOAD-500 / APPLY_DOWNLOAD-1200 / DOWNLOAD_SUCC-1000）与 `0x388`（TryUpPttReq / GetPttUrlReq）。
- **播放**：`AudioPlayer.java:266-273` —— `fsType >= 0` 用 `SilkPlayer`（skip 10 字节头 → 读 2B 长度 → 解帧 → AudioTrack），`< 0` 用 `AmrPlayer`（系统 MediaPlayer）。

## 2. 官方 Telegram Android

- **录制**：`MediaController.java:1119` `sampleRate = 48000`；`MediaController.java:5143-5145` `new AudioRecord(DEFAULT, 48000, CHANNEL_IN_MONO, ENCODING_PCM_16BIT, 1280)`。V2 采集 `utils/recorder/audio/AudioCapture.java:30-32`：`SAMPLE_RATE=48_000`、`FRAME_SAMPLES=960`(20ms)、`FRAME_BYTES=1920`。
- **编码**：`jni/audio.c:346`（V2 `:1315`）`opus_encoder_create(coding_rate, 1, OPUS_APPLICATION_VOIP, &r)`；`:227` `OPUS_BITRATE_MAX`（VBR 不封顶）；`:229` `frame_size = 960`。自写 Ogg 封装（OpusHead/OpusTags/preskip/granulepos）。native 库里还静态链了 ffmpeg 与 tgnet，统一打进 `libtmessages.49.so`。
- **时长**：`MediaController.java:1202` `recordTimeCount += fileBuffer.limit()/2/(sampleRate/1000)`；< 700ms 判太短不发送（`:5317-5325`）。
- **发送**：`TL_document`（mime `audio/ogg`）+ `TL_documentAttributeAudio`（`tgnet/TLRPC.java:1918`，voice=true、duration、waveform），经 `TL_messages_sendMedia`。
- **播放**：`audioPlayer = new VideoPlayer()`（`MediaController.java:3889`）= media3 ExoPlayer；本地有文件直接播，没有则 `tg://...` 流式（`ExtendedDefaultDataSource.java:188-190`）边下边播；进度 17ms 轮询 position/duration（`:1629-1685`），seek 按 0..1 比例（`:2637-2651`）。
- **波形**：native `getWaveform` 出 100 桶×5bit（63 字节）；`ui/Components/SeekBarWaveform.java:286/:376/:439-451` 每柱 3dp 槽、2dp 宽、最高 7dp，已播放部分叠 accent。

## 3. 对我方（纯 Dart，自实现 QQ 协议）的结论

现状（`lib/`）：接收入口已有 —— `lib/kernel/wlogin8/qq8_elem.dart:511 scanPtt()` 解 `RichText.ptt` 的字段 4(md5)/6(size)/19(秒)/20(直链后缀)，adapter 转成 `RecordSegment`（`lib/client_api/qq8_session_adapter.dart:804`），UI 只是占位行（`lib/ui/widgets/message_content.dart:169`，显示「语音 5″ 6.7KB」）。**播放没有、录制没有、上传没有。**

分期建议：

- **V1（可播可收，1 个迭代）**：下载直链（`grouptalk.c2c.qq.com`，字段 20 已能拼）→ 本地判断 `#!SILK_V3`/"#!AMR" → AMR 直接交系统播放器；SILK 用 FFI 调自编译 silk v3 解成 PCM16 再播（或先落 WAV）。UI 换成 TG 风格气泡（波形/时长/播放键）。
- **V2（可发）**：录制 PCM16 16k 单声道 → AMR-NB 编码（Android MediaRecorder 现成，`voiceType=0`，文件名 `md5 + ".amr"`）→ `cmd0x346 APPLY_UPLOAD` 拿 ip/ukey/uuid → HTTP 上传 → 组 `RichText.ptt` 发 `msgtype=-2002`。先做私聊（字段少），群聊要补 `file_id/group_file_key`。
- **V3（保真对齐官方）**：SILK v3 编码（FFI 自编译 libsilk，参数 16000/16000，10 字节头 + 2B LE 帧长），`voiceType=1`、`.slk`。
- **V4（体验）**：本地算波形（分桶峰值 → 0..31）、播放进度/seek/续播、录完自动播报、语音转文字（`cmd0x355`，服务端）。

风险与不可绕过的点：
1. **SILK 编解码没有纯 Dart 实现**，必须 native（FFI 载入 `libsilk`，需自编译 silk v3 SDK）。
2. **上传必须挂在 MSF 长连接上**（`0x346`），文件体走 HTTP；发送端只能在「已登录在线」时工作 —— 我们的架构天然满足。
3. 服务端是否接受 AMR（`voiceType=0`）需真机实测；官方协议保留该分支（文件名固定 `md5+".amr"`），但近年客户端基本都发 SILK。
4. iOS 无 AMR/SILK 原生播放，需自带解码（本项目只做 Android，可暂缓）。
