# TIM 抓包结论：语音上传走 highway（httpconn），不是 /qqcommfileupload

抓包：设备自带 `/system/bin/tcpdump`（root），`adb pull` 到 C:/Users/Administrator/.dsh/workspace/_ptt_tim2.pcap。
操作：TIM（com.tencent.tim，已登录 3499239040）在「晨曦」会话长按「按住 说话」2.5s，**成功发出「语音2秒」**。

## 1. TIM 的上传（成功路径）

    POST /cgi-bin/httpconn?htcmd=0x6FF0087&uin=2089495846 HTTP/1.1
    Host: 36.155.208.117:14000          ← 公网 IP，本 Wi-Fi 可达
    Accept: */*
    Connection: Keep-Alive
    User-Agent: Mozilla/5.0 (compatible; MSIE 10.0; Windows NT 6.2)
    Pragma: no-cache
    Cache-Control: no-cache
    Content-Length: 4690

    <body: highway 帧，明文可见 uin + "PicUp.DataUp" + 分片字节>

    回包 HTTP/1.1 200 OK, Content-Length: 144（内含 PicUp.DataUp / cookies 字样）

**要点**：
- 命令是 **`htcmd=0x6FF0087`**，与我们「离线文件上传」用的是同一个 servant（`lib/kernel/wlogin8/qq8_file.dart:416` 已经在跑）。
- 帧格式与我们 `Qq8File.buildHttpFrame` 一致：STX(0x28) + u32be 头长 + u32be 块长 + 头 PB + 数据 + ETX(0x29)；头里 `1:{1:1,2:uin,3:'PicUp.DataUp',4:seq,6:subid,8:cmdId}`、`2:{2:fileSize,3:offset,4:chunkLen,6:ticket,8:md5(chunk),9:fileMd5}`。
- 目标端口 **14000**、公网 IP —— 不是 8.2.11 老的 `/qqcommfileupload`。

## 2. TIM 的下载/播放（对照）

    GET /download?appid=1402&fileid=EhRKT5WNilAZnZhVsTGrAJQwpoXg7RjbGyD…&rkey=CAESqAEZ… HTTP/1.1
    host: 36.248.45.20
    → 200 OK, Content-Type: audio/mp3, Content-Range: bytes 0-3546/3547,
      User-ReturnCode: 0, body 以 #!SILK_V3 开头（3547 字节）

即「先 0x346 APPLY_DOWNLOAD 拿 URL → 普通 HTTP 取」，与我们 V1 收到的直链形态一致。

## 3. 我们的 V2 卡点（真机实测）

- 录音 → SILK → 0x346 申请 **全通**：`code=0, uuid=36B, uploadKey=170B, packSize=524288`。
- 但回执只给**运营商边缘 IP**：`11.180.100.34 / 11.180.101.29 / 11.187.145.160 / 11.187.144.217 / 30.176.98.77`，`port=80`，无 domain、无 dns。
- 本机（Wi-Fi 10.150.40.209/16，**无 SIM**）到这些地址 TCP 直接超时（adb ping 100% 丢包、PC curl 28）。

## 4. 结论与三条路

1. **改走 highway（推荐，但要拿通道地址）**：复用 `Qq8File.uploadHttp(buildHttpFrame, cmdId=0x6FF0087, service='PicUp.DataUp')`，把 SILK 字节传上去。
   - 缺的只有 **host:port + ticket**。TIM 用的是公网 14000 节点；我们 0x346 回执给的是 11.x（不可达）。
   - 可能来源：① `ConfigPushSvc.PushReq`(type=2) 下发的 bigdata `1281.3`（代码已解析并缓存 `_bigdataHost/_bigdataPort/_bigdataSigSession`，但**当前日志里没有「bigdata 会话已存」⇒ 这次登录没收到/没解析到**）；② 用不同 `net_type` 再申请一次，看服务端是否改派公网节点。
2. **先提交 V2（录音/编码/组包全部完成、264 个测试全绿），把「上传节点不可达」写成已知限制**，等能拿到 bigdata 通道再做。
3. **换网络验证**：插 CMCC SIM 用移动数据试同一条 8.2.11 老路径（我们这机器无 SIM）。
