# P2 直链刷新实验结论（2026-10-31）

## 1. 要回答的问题

图片占位「已失效 · 点按重试」的根因是直链过期（400 / `-5503007 download url has expired`）。
P0/P1 已把「失败可见 + 可重试」做完，但**重试永远失败**——因为存下来的 url 本身就死了。

于是 P2 的问题只有一个：**重新向服务端要一次这条消息，能不能拿到一条新的、可用的直链？**
如果能，就只需要「失效时重拉历史、覆盖 url」；如果不能，才必须去做富媒体下载（P3）。

## 2. 方法

新增 `tool/qq8_image_link_probe.dart`（真机协议工具，不进 lib）：

```bash
# 设备上取活票 + 身份（明文票据在 files/qq8/qq8-token-<uin>.json）
adb shell su -c 'cat /data/user/0/com.example.qqclient/files/qq8/qq8-token-<uin>.json' > _token.json
adb shell su -c 'cat /data/user/0/com.example.qqclient/files/qq8/identity.json' > _identity.json
adb shell am force-stop com.example.qqclient   # 同一 uin 不能两条会话并存

QQ_LIVE_CONFIRM=I_UNDERSTAND_THE_RISK dart run tool/qq8_image_link_probe.dart \
  --token-file=_token.json --identity=_identity.json \
  --gid=486045673 --begin=59120 --end=59140 --compare=_g3.jsonl
```

工具做三件事：登录态注册上线 → `MessageSvc.PbGetGroupMsg` 重拉指定 seq 区间 → 逐条打印图片元素的
`file / md5 / url`，并和本地 `group_486045673.jsonl` 里同 md5 的旧 url 做字符串比对。

样本：群 486045673 的 86 条落盘消息里 21 张唯一图片（10-29 ~ 10-31）。

## 3. 结果（真机实测，HA2CSJR5 / 2026-10-31 21:0x）

### 3.1 重拉回来的 url 与本地存的**逐字节相同**

seq 59137/59147/59153/59156/59162/59165/59167/59169/59170/59178/59179 共 9 张：`相同=true`，
连 `rkey=` 的值都一模一样。⇒ **服务端不重新签发直链**，rkey 是随消息生成、写死在元素里的。

### 3.2 有一张被「降级」了

seq 59175（md5 a8c5176b…）：本地存的是 `download?fileid=…&rkey=…` 的签名链接，
重拉回来变成 `gchatpic_new/0/0-0-A8C5176B…/0`（无签名）。
⇒ 重拉不但不刷新，**还可能把好链接换成差链接**。所以「重拉历史覆盖 url」这条路不能走。

### 3.3 url 形态与存活率（21 张，curl 实测）

| 形态 | 数量 | 结果 |
|---|---|---|
| `download?appid=1407&fileid=…&rkey=…&spec=0`（签名直链） | 11 | **10 张 400 `-5503007 download url has expired`**，1 张 200（最新那张） |
| `gchatpic_new/0/0-0-<MD5大写>/0`（只有 md5） | 8 | 6 张 404，2 张 200 |
| `gchatpic_new/<群uin>/<…-<MD5>/0?term=2&is_origin=0` | 2 | 1 张 200、1 张 404 |

### 3.4 能不能自己去「换 rkey」

对 3 张过期链接试了三种变形：

| 变形 | 结果 |
|---|---|
| 去掉 `rkey` 参数 | 400 `-5503010 invalid rkey` |
| `spec=0` 改 `spec=1` | 400 `-5503037 invalid spec or format` |
| 只剩 md5 的 `gchatpic_new/0/0-0-<MD5>/0?term=2` | 404（这一批已不在服务端缓存里） |

⇒ rkey 缺失/错误一律拒（`-5503010`），过期一律 `-5503007`。**客户端无法自造 rkey**。

## 4. 结论

1. **重拉历史刷新直链：不可行**（rkey 不重签，还有降级风险）。这一条可以封案，不要再试。
2. 直链有效期的真实边界：签名直链以小时计（10-29 的消息全部过期，10-31 那张还活）；
   md5 形式的链接取决于服务端缓存里还有没有原图 —— 一部分能 200，一部分 404。
3. 所以「图片过几小时就再也看不到」是**协议层事实**，不是我们的 bug；
   想稳定回看历史图片，只有富媒体下载（官方 `ImgStore.GroupPicDown` / `LongConn.OffPicDown`）。
4. 附带结论：**绝不能用重拉结果覆盖已存的 url**（3.2 的降级实证）。当前实现本来也不覆盖，保持。

## 5. P3 的范围（下一步）

- 现有资产：`lib/kernel/wlogin8/qq8_gfs.dart`（highway 上传通道）、`qq8_image.dart`（上传体/字段号）；
- 缺的是**下载**：`ImgStore.GroupPicDown`（群图）/ `LongConn.OffPicDown`（私聊图）的请求体 + highway 回包拼接；
- 关键输入其实就在我们手里：元素里那条过期 url 的 `fileid=` 参数就是服务端文件 fid，配上 md5/大小即可发起下载（不需要 rkey）；
- 官方侧需要取证：`com.tencent.mobileqq.transfile` 的 PicDownload 处理器与 `msf/core/ag.java:2232` 的命令字注册；
- 风险与工作量显著高于 P0/P1（新命令字 + highway 分片 + 断点），建议单独立项，先做「离线组包 + 真机单张验证」。

## 7. 遗留观察（不影响本结论）

- 8 张 md5 形式里有 2 张 200：说明部分历史图的 md5 兜底仍可用。当前把 `404 → missing` 的负缓存 TTL
  设成 7 天，会把这 2 张之外的「将来可能变好」也算成死图；要不要把 missing 的 TTL 缩短（比如 24h）
  属于策略选择，等 P3 决定后再一并定，避免现在来回改。
