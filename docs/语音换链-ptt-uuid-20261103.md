# 语音换链：把 ptt.3 的 uuid 落盘，rkey 过期后能换新直链

日期：2026-11-03　提交：见 git log

## 1. 先澄清现象：**接收本来就是好的**，只有"历史语音"会失效

真机日志（`/data/user/0/com.puretaoist31.penguinchat/files/logs/`）里有三次成功记录：

```
媒体下载成功 key=voice:46a8ee43f7d7fe9bde13f0de251426dc … bytes=18085 180ms   (2026-11-01 15:38)
媒体下载成功 key=voice:700f84ee…                      bytes=3763  170ms   (2026-11-01 15:50)
媒体下载成功 key=voice:caf81a52…                      bytes=6502  207ms   (2026-11-01 17:52)
```

pcap 里更能直接看到我自己发出去的那次 HTTP（`_ptt_tim2.pcap`，77 包）：

```
GET /download?appid=1402&fileid=OdZLS3GQaxYScEdRgYQkPKZjtnQm4NizRsL8RhcU-…&rkey=CAESqAEZHK6PzBro…
user-agent: Mozilla/5.0 (Linux; Android 13) penguinchat/1.0
→ HTTP/1.1 200 OK  Size: 3547  Content-Type: audio/mp3  Content-Range: bytes 0-3546/3547
  User-ReturnCode: 0   body = \x02#!SILK_V3!
```

所以：**`/download?appid=1402&fileid=…&rkey=…` 这个形态普通 GET 就能下**，前提是 rkey 新鲜。

## 2. 那为什么"过一天就听不了"

rkey 是**小时级**的。11-01 那 6 条收到的语音，到 11-02 全部返回
`{"retcode":-5503007,"retmsg":"download url has expired"}`。
消息里的 `down_para`（= ptt.20 的直链后缀）装的就是当时那条 rkey，所以历史语音
必须**重新申请**下载地址，跟群图换链（GroupPicDown）是同一类问题。

## 3. 换链要的不是 fileid，是 ptt.3 的 uuid（这是本节的关键取证）

- 用 `ApplyDownloadReq.str_fileid = 600` 发 1200：回包形态正确，
  `http://<ip>/download?appid=1402&fileid=&format=amr&rkey=<56B>`，
  但 **fileid 空、rkey 只有 56 字节**（合法 rkey 是 protobuf{1:4, 2:168B}）。
  拿它 GET 一律 `400 {\"retcode\":-5503023,\"retmsg\":\"appid is not match\"}`。
- 想"从 fileid 反推 uuid"：把 fileid protobuf 里的字段 2（20 字节）当 `bytes_uuid` 发过去，
  六种 owner×filetype 组合全部 `ret=-1`（`08ba0910…` 35 字节）。
  ⇒ **fileid 里没有 uuid，反推是死路**。
- fileid 的真实结构（解 `OdZLS…` 那条）：`{2:20B, 3:size, 4:appid(1402), 5:上传时间,
  6:"prod", 10:604800(TTL 7 天), 11:16B(md5), 15:2B, 16:"gz"}` —— 只有 md5/size/appid/TTL。

结论：**uuid 只能从消息元素 `ptt.3 = bytes_file_uuid`（36 字节 ASCII）里来**，
而以前收消息时根本没解析、也没落盘。

## 4. 改动（4 个源文件 + 3 个自测）

| 文件 | 改动 |
| --- | --- |
| `lib/kernel/wlogin8/qq8_elem.dart` | `Qq8VoiceElem` 新增 `uuid` 字段；`scanPtt` 解析 `ptt.3`（顺带把字段号注释补上 `3 = file_uuid`） |
| `lib/client_api/qq8_session_adapter.dart` | `Qq8VoiceElem` → `RecordSegment(…, uuid: uuid)` |
| `lib/client_api/segment.dart` | `RecordSegment` 新增 `uuid`，`toData/fromData` 一并补齐（落盘要能读回） |
| `lib/client_api/chat_store.dart` | 新增构造参数 `voiceUrlResolver`；`_refresherFor` 对 `RecordSegment` 返回换链闭包（无 uuid 返回 null，不发注定失败的 1200） |
| `lib/client_api/qq8_login_service.dart` | 新增 `resolveVoiceUrl({required String uuid})`：`apply-download(1200)` + `ownerType: ownerTypePeer(2)` → `parseApplyDownloadUrl` |
| `lib/client_api/qq8_providers.dart` | `ChatStore(voiceUrlResolver: service.resolveVoiceUrl)` |

复用的是图片那套机制：`MediaCache.ensure(refreshUrl: …)` 只在**主链分类为
expired/missing/rejected** 时换一次链，后台预取不换（否则打开会话就为整屏死链各发一个 WUP）。

**为什么 owner_type 必须是 2**：这是"别人的文件"。用 1（自己）拿到的是给上传方回读用的
BDH 地址（`http://<ip>:80/?ver=2&rkey=<170B DER>&voice_codec=0`），普通 GET 拿不到音频。

## 6. 四态口径

- **已实现**：ptt.3 uuid 解析与落盘；rkey 过期后凭 uuid 走 1200 换链并重下一次；
  没有 uuid 的老消息保持"已失效 · 点按重试"（诚实降级，不假装能修）。
- **离线已验证**：上面 4+2+6 项断言与三道门禁。
- **真机未验证**（本轮设备不在线，`adb devices` 为空）：需要 (a) 对端发一条**新**语音
  → 确认 uuid 落盘 & 立刻能播；(b) 等 1 小时以上再打开同一条 → 确认换链日志
  `语音换链成功 uuid=… → http://…/download?appid=1402&fileid=…&rkey=…` 且能播。
- **明确不支持**：BDH 协议下载（`PicDown`，我方上传的语音在服务端是 BDH 形态）；
  发送侧"对端能不能播"仍未定论（见下节）。

## 7. 发送侧仍开着的口子（不要误以为本次修好了）

我方上传 ptt 后，用同一条 uuid 发 1200（owner=1/2）拿到的是 **BDH 地址**而不是
`/download` 形态——官方客户端支持 BDH PicDown 所以理论上能下，但我方没有这条实现，
也无法在 PC 上验证。若对端仍报"消息已过期"，下一步是：
①抓一次官方客户端**发送**C2C 语音的明文包（8080）对比 ptt 元素（尤其 `ptt.7 bytes_reserve`）；
②实现 BDH PicDown 验证自己的文件能否取回。
