# 已读回执可行性（2026-11-01）

需求：Telegram 那种气泡右下角「单勾 = 已发出，双勾 = 对方已读」。

## 结论

**普通消息做不到。** QQ 8.2.11 里确实有已读回执的**协议通道**和**专用的「回执消息」**，
但没有「每条普通消息的已读状态」这种东西：

- 官方客户端**只对「回执消息」这一种特殊消息**显示「对方已读 / 对方未读」；
- 这个功能由**服务端开关**控制，默认关闭；开启后还有每天发送条数上限（默认 10 条）；
- 普通文本/图片消息没有任何字段能表示"对方读没读"，UI 里也没有对应图标。

所以本项目的处理是：**气泡只画单勾（服务端已接受）**，不再画双勾——原来那对勾
其实是把"已发送"画成了"已读"，属于误导。

## 证据（全部来自 analysis/_decompiled/jadx-main，QQ 8.2.11）

1. **协议定义** `tencent/im/msg/im_receipt.java`
   - `ReceiptReq`：`command`（field 1，默认 1）、`msg_info`（field 2）
   - `MsgInfo`：`uint64_from_uin`(1) / `uint64_to_uin`(2) / `uint32_msg_seq`(3) / `uint32_msg_random`(4)
   - `ReceiptResp`：`command`(1) / `receipt_info`(2)，`ReceiptInfo.uint64_read_time`
2. **发送侧** `com/tencent/mobileqq/app/MessageHandler.java:283-360`
   - `a(1, fromUin, toUin, msgSeq, msgRandom)` → 命令字 `MessageSvc.PbReceiptRead`，日志
     `sendReceiptMessageRead`（告知对方"我读了"）
   - `b(2, ...)` → 同一条命令字，`msgtype=2`（查询）
3. **响应侧** `MessageHandler.java:7800-7867`
   - `PbSendMsgResp.receipt_resp.receipt_info.uint64_read_time` 读出已读时间，
     再以 observer 6015 抛给上层：`{msgtype, msgseq}`（type=1）或
     `{msgtype, msgseq, readTime}`（type=2）
4. **上层分发** `defpackage/ajyv.java:515` `case 6015:` → `MessageObserver.a(long,long)` /
   `a(long,long,long)`。**除此之外全仓没有任何地方消费 6015**（grep 6015 只有这两处调用），
   也就是说这条链在 UI 层是断的。
5. **真正的功能是「回执消息」**：`resources/res/values/strings.xml:9088-9107`
   - `f8i` 对方已读 / `f8j` 对方未读 / `f8h` 0人已读 / `f8m` %1$s人已读
   - `f8n` 发送此消息可查看对方是否已读
   - `f8o` 发送此消息可查看对方是否已读(剩余%1$s次)
   - `f8d` 每天最多只能发送%1$d条回执消息 / `f8c` 查看回执消息，将告知%1$s你已读
6. **开关与配额来自服务端下发**：`defpackage/anbi.java:10376-10402`
   `handleReceiptConfig` 读 config 的 `kReceiptMsgEnable` / `kReceiptMsgMaxSendTimes`，
   写进 SharedPreferences（`defpackage/acre.java:25-46`：`receipt_kReceiptMsgEnable`
   默认 **0**、`receipt_kReceiptMsgSendTimes` 默认 **10**）。

## 为什么不"试一下"

- 对普通消息硬发 `MessageSvc.PbReceiptRead`：服务端没有对应的普通消息语义，最多返回错误；
  更糟的是万一命中"回执消息"逻辑，会给好友弹出一条「回执消息」提示——**这是明显的
  非官方行为特征**，属于账号风险，收益还是零（对方官方客户端也不会给我们回已读）。
- 想走「回执消息」正路：要服务端开关（我们开不了）、要每天限额、要发一条特殊消息给对方
  （对方会看到"回执消息"），与"像正常聊天"的产品目标相悖。

## 我们的实现

- `lib/ui/widgets/message_bubble.dart`：发送中 = `Icons.schedule`（时钟），
  失败 = `Icons.error_outline`，成功 = **`Icons.done`（单勾）**（原来三处都是 `Icons.done_all`）。
- 单测 `test/message_bubble_test.dart:205` 用例名与断言同步改成"已送达显示单勾"。
- 如果将来出现可靠的已读来源（比如我们自己实现的服务端，或官方开放该字段），只要把
  "成功"分支再按 `readTime != null` 分成单/双勾即可，改动点就这一处。
