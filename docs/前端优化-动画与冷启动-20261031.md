## 二、性能与结构上的硬约束（先看这段）

1. **L4 只能向下依赖**：新文件全在 `lib/ui/`，没有一个 import 到 L3 之外，也没让 L3 反过来认识 UI。
2. **测试注入面不能再扩大**：`test/ui_test.dart` / `test/home_page_test.dart` 只 override
   `dataDirProvider / backendRegistryProvider / safetyGateProvider`，**没有** `qq8ConnectControllerProvider`。
   所以「冷启动壳」只能放在 `lib/main.dart` 层（那里才有完整 DI），HomePage / SettingsPage / ChatListPanel
   的 build 一律不许 watch 它 —— 否则整批 UI 测试当场挂。
3. **`ui_settings.json` 的格式是契约**：`test/ui_test.dart:237-287` 逐字断言 `{"dark": bool}`。
   新偏好另起 `ui_prefs.json`，读坏了只影响自己。

## 四、每个决定的原因（免得后人当成随手写）

- **字号为什么只给四档**（0.9/1.0/1.1/1.2）：自由滑块会让行高、气泡内边距全落在没验证过的中间值上，
  TG 自己也是档位而不是连续滑块。档位名走 `UiPrefs.fontScaleLabel`，避免 UI 里散落 if-else。
- **为什么用 `MediaQuery.textScaler` 而不是给每个 TextStyle 乘系数**：一处生效、所有页面一致，
  包括第三方 widgets；乘系数要改几十处且必然漏。
- **气泡动画为什么必须判「新」**：`ListView.builder` 滚动会重建行，若每建一次都播动画，
  往回滚就是整屏气泡一起淡入。判据 = 开关开 && 没播过 && `now - m.time <= 8s`；
  8 秒这个数把「冷启动从磁盘载入的历史」全部挡在动画之外（那些消息时间都是旧的）。
  `_entered` 上限 400 条只为防长会话无界增长。
- **窄屏切换为什么要自定义 `layoutBuilder`**：`AnimatedSwitcher` 默认把新旧子树按各自尺寸居中排，
  两个全屏页面切换时会出现「先缩一下再展开」。改成 `Stack(fit: StackFit.expand)` 叠放交叉淡入。
- **冷启动壳为什么有 `minimumSplash = 650ms` 和 `maximumWait = 6s` 两个闸**：
  下限防止「闪一下就没」的廉价感（也避免 AnimatedSwitcher 抓不到中间态）；
  上限保证即使协议线卡住（真机上 PhSigLcId/GrayUinPro 检查曾各超时 7s）也一定进主页，
  **冷启动壳绝不能变成新的启动失败点**。
- **`AppBootstrap` 里为什么 `stage == idle` 也算 Settled**：没有存档票据时控制器停在 idle，
  这时等下去毫无意义，直接进主页（主页自己会显示「未连接」）。
- **页面转场为什么自己写 `PageTransitionsBuilder`**：Material 3 默认是 Android 的 zoom shared-axis，
  与 TG 的「轻淡入 + 微位移」观感差很远；一个类替换全平台，不用逐页写 `PageRouteBuilder`。

## 五、冷启动时序（真机可对照日志看）

1. `main()` 装好 7 个 override → `QQClientApp` → `AppBootstrap`。
2. `AppBootstrap.initState` 首帧后 `ref.read(qq8ConnectControllerProvider)`（构造即
   `autoLoginIfSaved()`，即「后端账号随冷启动加载」）。
3. 品牌页可见，状态行随 `qq8LoginStateProvider` 变化：
   `connecting → 「正在恢复账号 <uin>…」`、`online → 「已恢复，正在进入…」`、
   `needs* → 「需要重新验证…」`、`sessionExpired/rejected → 「需要在设置里重新登录」`。
4. 满足「≥650ms 且 stage 已 Settled」→ `AnimatedSwitcher(260ms)` 换 HomePage。
