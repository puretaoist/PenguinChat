## W1 连接生命周期（缺陷2）

- `Qq8Transport` 新增 `set onDisconnected(void Function(Object error)? cb)`；TCP 实现在 `onError`/`onDone`/`write` 失败/`send` 失败时各报一次（同一连接只报一次，主动 `close()` 不报）；脚本传输加 `emitDisconnect()`。
- `Qq8Session` 新增 `onConnectionLost(Object error)`；`_handleTransportDown` 把错误包成 `Qq8TransportException("连接已断开")` → `_failAllPending` → 各触发一次 `onConnectionLost`/`onOffline`（幂等）。挂起的请求**立即终结**，不再空等 30s。
- `_send` 加 `_down` 前置判断；`_awaitResponse` 改为「IIFE async 闭包 + `work.timeout(timeout)`」，把 `write` 也纳入总时限，首发与 -10008 重发**共享同一 deadline**；`finally` 里 `work.ignore()` 吞掉超时后迟到的失败。
- 新增 `resendStormSuspected`（`qq8ResendStormThreshold=3` / `qq8ResendStormWindow=30s`）：连续 3 次重发耗尽即置位；`_pullNewMessages` 在**轮询触发**时据此跳过一轮（用户主动补拉不受限）。
- `qq8_login_service.dart` 新增 `_sessionEpoch`，`_teardownConnection`/`_goOnline` 各自增；`_handleConnectionLost` 校验 `identical(session)` + epoch + stage ∈ {online, connecting} 才 `emit(disconnected)` 并 `reconnect(uin:)`。`_registerInBackground`/`_runOnlineChecks`/上线补拉都带 epoch 校验，旧任务落幕即失效。
- 测试：`tool/qq8_session_selftest.dart` 第 7 节（挂起请求立即终结、原因文案、幂等、风暴阈值、共享 100ms 总时限实测 <125ms）→ 62 项；`tool/qq8_login_service_selftest.dart` 第 10 节（`emitDisconnect()` 连报两次 → 自动恢复 online、状态流含 disconnected、只建 2 条连接）→ 127→136 项。

## W2 注册三态（缺陷1）

- `enum Qq8RegisterOutcome { confirmed, rejected, unconfirmed }` + `Future<Qq8RegisterOutcome> registerWithOutcome({bool logout, Duration timeout})`：`register()` 成功→confirmed，返回 false→rejected，异常（含超时）→unconfirmed。
- `qq8_login_service.dart`：`registerTimeout`（默认 30s，测试可调小）、`_registerOnce()` single-flight（在途复用）、`_pushChannelUnconfirmed`。分流：
  - confirmed → 日志「上线注册已确认（cReplyCode=0）」；
  - unconfirmed → `_pushChannelUnconfirmed=true`，日志「上线注册无回执（等价 icqq -2）：推送通道未确认，继续上线并保底轮询」，**stage 不动**（仍上线）；
  - rejected → 原逻辑 `emit(failed)`（文案「登录已通过，但上线注册被拒（票据或设备信息不符）」）。
- `_runOnlineChecks` 开头若 `_pushChannelUnconfirmed` 就**直接跳过**两条回放检查（省 16s 空等，日志说明「回放仅作诊断」）；`StatSvc.QueryHB` 分支改走 `_registerOnce`，不再并发叠注册。
- 测试：第 11 节 A/B/C 三态（含「脚本不回 register + `registerTimeout=250ms`」），断言 C 情形 stage 仍 online、`pushChannelUnconfirmed=true`、在线检查被跳过。
- 诚实边界：本轮只是**把「不知道」如实标成 unconfirmed**，没有让推送真正到达。业务 push 仍未来，轮询兜底保持不变（每 60s）。

## W4 图片首屏（缺陷3）

**根因（离线可证的部分）**：`ChatStore._prefetchMedia` 是尽力而为的暖缓存——插入那一刻缓存索引未就绪、或这次下载失败，就再没有第二次机会；而气泡的 `_ImageBlock` 原来纯展示，不会主动补下载。于是「首屏只有文件名占位卡，重启（重新加载会话 → `_loadMessages` 再预取一次）才出图」。

**修法**：`_ImageBlock` 由 `StatelessWidget` 改成 `StatefulWidget`，新增可选 `ensureMedia` 钩子，首帧没有本地文件时在帧后**补一次**下载，成功后 `setState` 换成 `Image.file`。
- 每条媒体只补一次（`_ensureTried` 记键）；失败也算试过，避免重建一次就重刷一次 CDN 404。
- 已存在本地文件、闪照、未接钩子三种情况都不发请求，旧行为不变。
- 钩子链：`home_page.dart` 传 `store?.ensureMedia` → `MessageBubble` → `MessageContent` → `_ImageBlock`（全部可选参数，纯展示层不依赖 Riverpod）。
- 测试：新建 `test/message_content_test.dart` 3 条用例——补一次下载后占位换真图（`ensureMedia` 调用数 == 1）、无钩子保持占位不崩、本地已有文件时不发请求。
- **真机未复验**：需要在装新包后重收一张群图，确认首屏即出图；若仍占位，日志里应能看到 `ensureMedia` 的失败原因（下一步再加点）。

## W5 历史幽灵气泡（缺陷4）

- 判定收在纯函数 `Qq8SessionAdapter.isDeletedPlaceholder(m)`：`m.time <= 0 && m.fromUin == 0 && m.text == "[已删除]"` 三条件齐全才算——**不按中文文本单独匹配**（正常消息也可能带这几个字）。
- `_toChatMessage` 返回 `ChatMessage?`，命中占位就记日志并丢弃；三处调用点（私聊历史 / 群历史 / `_onPush`）改为 `map(...).whereType<ChatMessage>()`。
- 关键：历史页「还有更早」的判据改用**原始页**（`page.messages.isNotEmpty`），不能再用过滤后的列表——否则整页都是占位时会被误判成「到头」，游标停滞、旧消息永远拉不回来（对应策划里的「原始 seq 进度与可展示消息双轨」）。
- 测试：`tool/qq8_session_adapter_selftest.dart` 第 5b 节（三条件齐才丢；发送者非 0 / 正文正常 / 有时间有发送者的 `[已删除]` 全部保留）→ 84 项。放在第 10 节之前且为纯函数调用，避免共享 scripted 队列的 seq 配对错位。
