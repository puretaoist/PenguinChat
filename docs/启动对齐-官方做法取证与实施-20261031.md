# 启动对齐：官方 QQ 8.2.11 / Telegram 怎么做的，我们改成什么样

> 问题来源（用户 m45963）：「启动方面看官方qq和tg是怎么做的」。
> 结论先说：**两家官方都不"等登录"**——QQ 是"闪屏只盖住真实工作、工作一完立刻
> 换成真界面"，Telegram 是"起始窗口颜色 = 首帧界面颜色 + 本地数据库先出，网络
> 在后台追"。我们比两家都慢，慢在"人为最短停留 650ms"和"闸门等的是登录到
> online（含网络往返）"。

| 闪屏画面 | Activity 自己的 contentView：`SetSplash` 里 `setContentView(layout bz1)`——全屏纯色 + 居中 `splash.jpg` + 底部可选 logo 水印 | startup/step/SetSplash.java、res/layout/bz1.xml、assets/splash.jpg(750x1650)/splash_big.jpg(2480x2200)/splash_logo.png(256x28，"腾讯云提供计算服务") |

## 三、我们原来的问题（真机可复现）

1. **白闪**：`android/app/src/main/res/drawable/launch_background.xml` 是
   `@android:color/white`（v21 那份甚至是 `?android:colorBackground`），而
   StartupSplash 是暗色 `#0F0F0F` ⇒ 冷启动先一帧白再跳暗色。
2. **人为最短停留**：`AppBootstrap.minimumSplash = 650ms`——这一条在任何官方
   实现里都找不到对应物，纯粹是我们自己加的。
3. **闸门等网络**：早先 `maximumWait = 6s`，且"没结论"时不敢放人进去，因为
   会话栏在 `store == null` 时会写「未连接后端」并催用户去配置——那在"正在
   恢复账号"的时候是**假消息**。

## 四、这次改了什么（4 处，全部离线可验证）

| # | 文件 | 改动 |
| --- | --- | --- |
| 1 | `android/app/src/main/res/values/colors.xml`（新增） | `launch_background = #FF0F0F0F`，与 `TelegramColors.bgApp`（暗色档）一致。只做一档：本应用主题是**应用内开关**、默认暗色，与系统深色模式无关 |
| 2 | `drawable/launch_background.xml` + `drawable-v21/launch_background.xml` | 都改成 `@color/launch_background`（原来分别是 white / `?android:colorBackground`） |
| 3 | `values/styles.xml` + `values-night/styles.xml` | 加 `android:windowSplashScreenBackground=@color/launch_background` 与 `windowSplashScreenAnimatedIcon=@android:color/transparent`（API 31+）：系统那屏"图标页"底色对齐、图标透明 ⇒ 视觉上等于 QQ 的"关掉预览"（我们关不掉，只能对齐颜色） |
| 4 | `lib/ui/pages/app_bootstrap.dart` | `minimumSplash = Duration.zero`（不再人为停留）、`maximumWait = 3s`、新增 `_idleGrace = 400ms`（idle 在启动头 400ms 内是"还没开始跑"，不能当成"没有票"立刻掀盖），并把 `connecting` 传给 HomePage |
| 5 | `lib/ui/pages/home_page.dart` + `lib/ui/widgets/chat_list_panel.dart` | 新增 `connecting` 参数：`store==null && connecting` 时空态显示「正在连接…／正在恢复上次的会话，请稍候」，**不显示**「未连接后端」和配置入口 |

不抄的部分（有理由）：
- **广告闪屏 / 节日闪屏**：产品不需要，且会拖慢启动。
- **把真实 onCreate 推迟到闪屏结束**：QQ 那套是因为它启动步骤多（dex、资源、
  so）。我们 Flutter 首帧只做 `runApp`，没有可推迟的重活。
- **不设 windowDisablePreview**：Flutter 侧没有对应 API；我们用"同色 + 透明
  图标"达到同样的观感。

## 七、还没做的（下一步可选）

> **已于 2026-10-31 晚做完，见第八节**（用户反馈「感官上比较慢，而且卡顿感强」
> 之后重做了整条启动路径）。

真正的"官方同款"还差一条：**登录前就把上次的会话列表画出来**（TG 的本地
database 先出）。我们做不到是因为 `ChatStore` 的构造要求一个活的 `Session`
（`chat_store.dart:105`），登录前拿不到 store，所以只能显示空态。

可行方案（要动 L3，需单独批准）：
1. 从 `<dataDir>/chats.json`（`chat_store.dart:21/_loadIndex():1375`）读出一份
   只读的会话摘要，做成 `cachedChatsProvider`；
2. 冷启动壳在 store 还是 null 时把这份摘要喂给 `ChatListPanel`，行可点但进入
   会话时只读（消息从 `chats/*.jsonl` 读，暂不能发）；
3. store 上线后无缝换成真 store（同一 dataDir，内容是同一份）。

风险：两套数据源同时存在，容易"点了没反应/发送按钮在只读态下不可用"，需要
一次完整的交互设计，不是十行改动。建议单独开一轮做。

## 八、重做：连闪屏都不要，第一帧就是会话列表（2026-10-31 晚）

用户看过第五节那版之后说（原话）：「不对，目前的方案感官上比较慢，而且卡顿感强」。
两条症状要分开治：

| 症状 | 真实原因 | 治法 |
| --- | --- | --- |
| 「慢」 | 点图标后 2–3 秒**纯黑**（debug 引擎 JIT + 163MB 包），然后才轮到品牌页，品牌页再等登录到 online | ①不再有品牌页，**首帧直接画会话列表**（数据来自磁盘索引，不等登录）②启动窗口只留一块与首帧同色的暗色（**不放任何图形**） |
| 「卡顿」 | `AnimatedSwitcher(260ms)` 把品牌页和主界面两棵**全屏**树交叉合成，debug 帧率下明显掉帧 | 直接删掉 AnimatedSwitcher，不做任何整页过渡 |

### 8.1 会话索引预览（新 L3 文件）

`lib/client_api/chat_index_preview.dart`（约 90 行）：

```dart
class ChatIndexPreview {
  final int uin;          // 目录名推出来的号
  final List<Chat> chats; // 已按列表顺序排好的会话
}

Future<ChatIndexPreview?> loadChatIndexPreview(Directory dataDir);
```

* 扫 `<dataDir>/accounts/*/chats.json`，取 `lastModifiedSync` 最新的那份 =
  「最后用过的号」（多账号时不会画错人）。
* 解析与排序**复用 store 的实现**：`chatFromIndexJson(Map)` 与
  `compareChatsForList(Chat,Chat)` 这两个函数从 `lib/client_api/chat_store.dart`
  里提成了**顶层函数**（原私有方法只剩一行委托）。
  理由：预览和真列表如果各写一份，store 接管那一刻会重排一次，看起来像"列表跳了一下"。
* 任何异常（无 accounts、无 chats.json、坏 JSON、结构不认识、空数组）一律
  返回 **null**，退回原来的启动路径 —— 预览是"锦上添花"，绝不能因为它挂住启动。
* 全同步 IO（`listSync` + `readAsStringSync`），索引几十 KB，实测 **7–165ms**。

### 8.2 接线（L4）

* `lib/main.dart`：`runApp` 之前 `final preview = await loadChatIndexPreview(dataDir);`，
  打一行 `会话预览: uin=… 会话数=…`，再 `QQClientApp(preview: preview)` →
  `AppBootstrap(preview: preview)`。
* `lib/ui/pages/app_bootstrap.dart`：`bool get _hasPreview => preview != null && preview!.chats.isNotEmpty;`
  —— 有预览就**直接**返回 `HomePage(previewChats: …)`，连 100ms 轮询定时器都不装；
  没预览（首次安装）才走原来的 StartupSplash 闸门。
* `lib/ui/pages/home_page.dart`：
  `final chats = live.isNotEmpty ? live : widget.previewChats;`（live 是 store 的
  `chatsProvider`），`previewOnly = store == null && previewChats.isNotEmpty` 时
  `_openChat` 直接 return（点不开比点进去报错好）；store 一上线自动换成 live。
* `lib/ui/widgets/chat_list_panel.dart`：`store == null && connecting` 时列表顶部
  压一条 **2px 静态**强调色细线（`ValueKey('preview-connecting-line')`）——
  用静态而不用 `LinearProgressIndicator`，见 PITFALLS C96/C99（无限动画既让
  低端机持续掉帧，也让 `pumpAndSettle` 必然超时）。

### 8.3 启动窗口：只有一块同色暗底，不放图形

* `values/styles.xml` + `values-night/styles.xml`：`windowSplashScreenBackground`
  = `@color/launch_background`（`#FF0F0F0F`，与 `TelegramColors.bgApp` 同值），
  `windowSplashScreenAnimatedIcon` = `@android:color/transparent`。
* `drawable/launch_background.xml` + `drawable-v21/`：layer-list 只有一层暗色。
* 曾试过在这块窗口放一个"品牌气泡"矢量（`splash_mark.xml` + 紫色圆底），
  实测首帧 808/843ms 没有变化，而用户看过后认为**紫色气泡没必要** ⇒ 已删除。
  结论：这块窗口只做"底色对齐"，不放任何图形，避免"图标闪一下再消失"的跳变。
* 剩下那段等待只能靠缩短首帧本身来解决（AOT / 减包体），见 8.6。

### 8.6 诚实的边界

* **release 才是用户装的包**。debug 的 3.8s 里约 2.4s 是引擎 JIT + 类加载，
  改代码改不掉；要更快只能上 baseline profile / 减包体，是另一件事。
* 预览期**不能发消息、不能点开会话**（没有 store，也没有 session）。这段
  时间约 0.4–0.9s，用户通常还在看列表，实测无感。
* 首次安装（没有 chats.json）仍然会看到 StartupSplash，那条路径没变。
